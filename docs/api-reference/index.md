# API Reference

Every page under this section is **generated**, not hand-written:

- **REST** pages are generated by
  [`docusaurus-plugin-openapi-docs`](https://github.com/PaloAltoNetworks/docusaurus-openapi-docs)
  directly from each context's own `apis/openapi.yaml` — the same
  Spectral-linted spec each service ships and gates its own CI on.
  Regenerate with `npm run gen-api-docs:all`.
- **Async** pages embed static HTML generated by the official
  [AsyncAPI Generator](https://github.com/asyncapi/generator)
  (`@asyncapi/html-template`) directly from each context's own
  `apis/asyncapi.yaml`. Regenerate with `npm run gen-async-docs:all`.

Both source spec sets are copied verbatim from each context repository's
`origin/develop` branch into this repository's own `apis/<context>/`
directory — see [contributing](https://github.com/claudioed/warehouse-docs#readme)
for the sync procedure. Nothing under this section is transcribed by hand.

process-path-management · labor-performance (+ a dedicated `reports` API)

## Contexts with an Async (Kafka) API

inventory-storage · wes-work-planning · fulfillment-execution ·
workforce-management · process-path-management · labor-performance ·
order-management publishes no Kafka events in v1 (local log publisher only —
see [order-management's domain events](/contexts/order-management/domain-events)).
`facility-layout` publishes no events consumed by anyone yet, and has no
`apis/asyncapi.yaml` at this time.

## warehouse-ops-agent

`warehouse-ops-agent` has no `apis/openapi.yaml` — its REST and MCP surface
is small and changing fast enough that it is documented in prose. See
[warehouse-ops-agent's API surface](/api-reference/warehouse-ops-agent).
